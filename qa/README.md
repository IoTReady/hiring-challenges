## Part 1 — Bug Report

A customer sends this support message:

> "The app doesn't work on my phone sometimes."

You cannot reach the customer right now. You have tried to reproduce the issue yourself but cannot.

Write two things:

1. The bug report you would file internally — ready for a developer to pick up without asking you anything further.
2. The follow-up questions you would send to the customer — only what you actually need, not a generic checklist.

---

## Part 2 — Test Case Design

You are testing this feature in a SaaS web app:

**"Invite a team member by email."**

The entire spec is:

> Users can enter an email address and tap Send Invite. The invitee receives an email with a join link valid for 48 hours.

Write your test cases. Any format is fine. Do not ask for clarification — infer what a reasonable implementation would do, then test its edges.

## Part 4 — Investigation Scenario

Support escalates this issue:

> Three customers using the mobile app are seeing sensor readings that are 2–3 minutes stale. The web dashboard for the same device shows live data. It only happens after the phone has been in the background for a while. Restarting the app fixes it.

You have access to: the mobile app, the web app, browser DevTools, and a tool to trigger test device events from the backend.

Write your investigation plan: your hypotheses, the order you'd test them, and what evidence would confirm or rule out each one.
